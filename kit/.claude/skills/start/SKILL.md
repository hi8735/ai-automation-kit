# /start — 업무자동화 인터뷰

목표: 이 사람이 **한 세션만으로, 스스로**, 본인 업무에서 **실제로 쓸 수 있는** 자동화 방식을 찾게 돕는다. 조건이 맞으면 첫 자동화까지 만든다.

이 인터뷰의 품질은 **초반(직무 이해와 업무 발굴)** 에서 결정된다. 서두르지 말고, 이 사람의 실제 하루와 실제 업무를 손에 잡히게 이해할 때까지 묻는다. 대화 원칙은 `CLAUDE.md` 를 따른다 — 특히 **질문은 한 번에 하나**.

## 0단계 — 환영과 점검

1. **이전 기록 확인.** `results/interview.md` 가 있으면 읽는다.
   - 있으면: "지난번에 ○○까지 이야기했어요. 이어서 할까요, 처음부터 할까요?" 하고 기록의 `stage` 부터 이어간다.
   - `stage` 가 `done` 이면(리포트까지 끝냄): 번호 선택지로 묻는다 — 1. 다른 업무를 하나 더 찾아보기 2. 만든 자동화 고치기 3. 처음부터 새로. 1번이면 기존 후보 목록에서 이어가고, 기존 기록은 지우지 않고 아래에 덧붙인다. 처음부터 새로 하려면 기존 기록을 지우기 전에 반드시 확인을 받는다.
   - 기록의 `kit_version` 이 지금 키트 버전과 달라도 그대로 읽고 이어간다. 새 버전에 생긴 항목(예: `daangn_nickname`)이 비어 있으면 필요할 때 묻는다.
   - 없으면: 아래로.
2. **조용히 환경 점검** (사용자에게 묻지 말고 직접 확인, 문제 있을 때만 말한다).
   - 현재 폴더에 `inputs`, `results`, `report` 가 있는지. 없으면 `CLAUDE.md` 의 "실행 위치 점검" 대로 안내.
   - 운영체제 (Windows / Mac).
   - Python 유무 — `guide/python-setup.md` 의 "있는지 확인하는 법" 대로. 결과는 기록에만 적고 지금은 말하지 않는다.
3. **환영** — 짧게, 아래 내용을 자연스럽게:
   - 30~60분 정도 이야기 나누면서 자동화할 만한 일을 같이 찾는다. 중간에 끊겨도 다시 `/start` 하면 이어진다.
   - 끝에 진행자에게 보낼 리포트를 만드는데, 회사 정보는 모두 지운 형태로 만들고 보내기 전에 본인이 확인한다.
   - 파일 안내 한 줄: "나중에 업무 파일이나 화면 캡처를 보여주시면 훨씬 정확해지는데, 넣어주신 파일은 Claude 로 전송돼요. 회사 규정을 한번 확인해 주시고, 가능하면 민감한 부분을 지운 샘플을 써주세요."
4. **당근 닉네임.** "먼저 당근 모임 채팅방에서 쓰시는 닉네임을 알려주세요. 리포트에 그 이름으로 적어야 진행자분이 찾아서 1:1 연락을 드릴 수 있어요." — 기록의 `daangn_nickname` 에 저장. 대화에서는 따로 원하는 호칭이 없으면 이 닉네임으로 부른다 (`call_name`).

## 갈래 선택

반드시 **번호 선택지**로 보여준다. 두 갈래가 있다는 걸 사용자가 알아야 고를 수 있다.

> 시작하기 전에 하나만 골라주세요.
>
> **1.** 자동화하고 싶은 일이 이미 있어요
> **2.** 아직 구체적이진 않아요 — 제 업무를 설명하면서 하나씩 찾아보고 싶어요
>
> 번호로 답해주시면 돼요. 애매하면 2번이 좋아요.

- 1번 → `references/track-1-clear.md` 를 읽고 진행.
- 2번 → `references/track-2-explore.md` 를 읽고 진행.
- 진행 중에 갈래를 바꾸는 게 맞아 보이면 (1번인데 그 일이 자동화에 안 맞거나, 2번인데 갑자기 분명한 후보가 나오면) 이유를 말하고 바꿀지 묻는다.

## 공통 — 깊이 파기와 진단

두 갈래 모두 후보 업무 하나가 정해지면 `references/deep-dive.md` 를 읽고 진행한다.

## 마무리 분기

진단이 끝나면:

- **A 등급이고 샘플 파일이 있으면** → "지금 바로 만들어볼까요? 20~40분 정도 걸려요." → 좋다고 하면 `/build` 스킬의 지침을 읽고 이어서 진행한다 (사용자가 명령을 다시 칠 필요 없음).
- **A 등급인데 샘플이 없으면** → 어떤 파일을 어떻게 준비하면 되는지 구체적으로 알려준다 (가린 샘플 만드는 법 포함). 준비되면 `/build` 로 이어갈 수 있다고 안내.
- **B·C·D 등급이면** → 무엇이 있으면 가능한지, 또는 왜 맞지 않는지 솔직하게 정리한다. 같은 사람의 다른 후보 중 A 등급이 있으면 그걸로 첫 자동화를 해볼지 묻는다.
- 어느 경우든 마지막엔 `/report` 로 리포트를 만들 수 있다고 안내한다.

## 기록

- 각 단계가 끝날 때마다 `results/interview.md` 를 갱신한다. 형식: `references/record-format.md`.
- 사용자가 말한 내용은 그 사람의 표현을 살려서 적는다 (요약하더라도 핵심 단어는 그대로).
