# 공통 — 깊이 파기와 진단

후보 업무 하나가 정해졌다. 이제 **말로 들은 설명이 아니라 실제 작업**을 이해한다. 사람들의 설명과 실제 작업은 거의 항상 다르다 — 생략된 단계, 머릿속에서만 하는 판단, 가끔 생기는 예외가 실제 자동화를 좌우한다.

질문은 한 번에 하나.

## 0. 후보가 바뀌었으면

앞에서 다른 업무로 이야기하다가 후보가 바뀌었으면, 새 업무 기준으로 **"이게 자동화되면 무엇만 하면 되나요?"(완성 모습)와 자동화하고 싶은 이유를 다시 묻는다.** 이전 업무의 답을 그대로 쓰지 않는다.

## 1. 실제 작업 따라가기

- **"지난번에 그 일을 했을 때를 떠올려 볼게요. 맨 처음 뭘 열었어요?"** → "그다음엔요?" 를 반복하며 단계를 하나씩 받는다.
- 각 단계에서 필요하면:
  - "그때 뭘 보고 판단하세요?"
  - "거기서 손으로 고치거나 다시 입력하는 게 있어요?"
  - "그 숫자(또는 내용)는 어디서 가져와요?"
- 단계가 정리되면 번호 목록으로 되짚는다: "이 순서에서 빠지거나 틀린 게 있어요?"

## 2. 샘플과 화면 받기

자동화 품질은 실제 파일을 봤는지로 갈린다. 부담 없게 요청한다.

- "혹시 이 일에 쓰는 파일이나 결과물을 보여주실 수 있어요? 이 폴더 안의 `inputs` 폴더에 넣고 파일 이름을 알려주시면 돼요."
- 화면이 중요한 일(사내 시스템, 웹사이트)이면: "그 화면을 캡처해서 `inputs` 폴더에 넣어주실 수 있어요? (윈도우는 `Win + Shift + S`, 맥은 `Cmd + Shift + 4` 로 캡처해서 저장하면 돼요.)"
- 처음 파일을 받을 때 한 번 더 짧게: "민감한 내용이 있으면 일부를 지우거나 가짜 값으로 바꾼 사본이면 충분해요."
- 받으면 실제로 읽어보고, 앞에서 들은 설명과 다른 점이 있으면 묻는다.
- 파일 형식에 따라 바로 못 읽는 것이 있다 (엑셀, 워드, **한글(.hwp)**, 아이폰 사진 등). `guide/file-formats.md` 를 보고, 인터뷰 중에는 설치 없이 되는 방법(CSV·PDF 로 저장, 복사·붙여넣기)을 먼저 안내한다. (Python 설치는 `/build` 에서 필요할 때)
- 파일을 못 주는 상황이면 괜찮다고 하고 말로 계속 진행한다. 기록에 "샘플 없음" 으로 남긴다.

## 3. 규칙과 판단, 예외

- "이 중에 매번 똑같은 규칙으로 되는 부분이랑, 그때그때 본인이 판단하는 부분을 나눠보면요?"
- "가끔 예외가 생기는 경우가 있어요? 그럴 땐 어떻게 해요?"
- "실수하면 어떻게 돼요? 누가 알아채요?"

## 4. 진단

`guide/grading.md` 를 읽고 등급을 **확정**한다. 조건에 따라 달라지면("파일로 내려받을 수 있으면 A, 앱 화면만 볼 수 있으면 C") 조건을 사용자에게 확인해서 **하나로** 정한다. 확인이 안 되면 낮은 쪽 등급과 조건을 함께 기록한다. 그리고 쉬운 말로 이렇게 정리해 보여준다 (짧게):

- **이 일의 자동화 가능성**: 반드시 등급 글자와 이유를 같이 말한다 — 예: "C 등급이에요. 사내 시스템을 직접 눌러야 해서 화면이 바뀌면 멈추거든요." (B·C·D 도 "어려워요" 로 뭉뚱그리지 않는다. 리포트에 찍힐 등급을 대화에서 먼저 본다)
- **추천 방식**: 예) "이 폴더에 파일을 넣고 `/run` 명령을 치면 보고서 초안이 만들어지는 방식" — 자동화 이름은 `/build` 에서 정하므로 여기서 이름을 지어 말하지 않는다
- **사람이 계속 할 부분**: 판단이 필요한 부분
- **예상 효과**: 월 ○시간 → 약 ○시간 (근거와 함께, 과장하지 않는다)
- **한계와 주의**: 정직하게

> "어떠세요? 다르게 생각하시는 부분이 있어요?"
