01

왜 이 세션을 열었나

저는 개발팀에서 백엔드를 이끌고 있어요. 지금은 일하는 환경이 꽤 탄탄하게 갖춰져서, 슬랙 메시지 하나만 읽혀도 Claude 가 노션 같은 곳에서 맥락을 찾아보고, 일을 작은 단위로 나눠 스스로 설계하고, 코드를 써서 리뷰 요청(PR)까지 올립니다.

문제가 생겼을 때도 비슷해요. 모니터링 도구, 코드, 데이터베이스를 함께 훑어서 원인을 빠르게 좁혀 오고, 손으로 하던 위험한 작업은 정해진 절차(스킬)로 만들어 두어서 예전보다 몇 배 안전하게 처리합니다.

그렇게 생긴 시간에 팀을 이끄는 일을 훨씬 많이 볼 수 있게 됐어요. 그러다 보니 궁금해졌습니다. 개발이 아닌 다른 직무에도 이런 자동화가 들어갈 자리가 있을까?

그래서 이 세션을 열었고, 감사하게도 정말 많은 분들이 와 주셔서 생각보다 훨씬 다양한 일을 같이 들여다볼 수 있게 됐어요.

02

제 일은 이렇게 돌아가요

회사 코드 전체를 한 폴더에 모아 두고, Claude 가 일할 때 필요한 것을 다섯 겹으로 깔아 뒀어요.

1
맥락 — 무엇을 알고 일하나 백엔드·웹·앱·배포 설정까지 회사 코드 전체 + 코드 지도, 도메인 위키, 일하는 규칙 문서. 신입 온보딩 자료를 Claude 에게 주는 셈이에요.
2
연결 — 어디를 직접 볼 수 있나 슬랙, 노션, 지라, 깃허브, 모니터링 도구를 Claude 가 직접 읽어요. 사람이 복사해서 붙여 줄 필요가 없어요.
3
절차 (스킬) — 어떻게 일하나 "작업 쪼개기", "PR 올리기", "코드 리뷰", "장애 진단", "배포 감시", "아침 브리핑" 같은 일하는 방식을 40여 개의 절차로 적어 뒀어요.
4
안전장치 — 무엇은 하지 않나 계획은 제가 확인한 뒤에 실행, 운영 데이터는 읽기만, 롤백 같은 결정은 경보만 하고 사람이 해요.
5
배움 — 다음엔 더 잘하게 제가 "그게 아니라…" 하고 고쳐 준 것은 규칙이나 절차로 승격돼요. 하던 일은 인수인계 문서로 남겨서 다음 날 그대로 이어가요.

그래서 하루 일이 이렇게 흘러가요

새 기능
  1. 슬랙 요청 읽기
  2. 노션·지라에서 맥락 찾기
  3. 리뷰하기 좋은 크기로 작업 쪼개기
  4. 제가 계획 확인
  5. 코드 작성·테스트·규칙 검사
  6. PR 올리기
문제 발생
  1. 알림 확인
  2. 모니터링 기록 훑기
  3. 관련 코드·데이터 확인
  4. 원인 좁히기·재현
  5. 제가 판단
  6. 수정 PR·회고 문서
반복 수작업
  1. 자주 하는 수동 작업 찾기
  2. 절차를 스킬로 적기
  3. 검증 단계 넣기
  4. 위험한 동작은 막기
  5. 다음부터 한 줄로 실행
03

오늘 키트도 같은 구조예요

규모만 작을 뿐, 여러분이 받은 키트도 같은 다섯 겹으로 만들었어요.

제 업무 환경오늘 키트
회사 코드·문서·규칙→인터뷰에서 정리한 내 업무 기록
슬랙·노션·모니터링 연결→inputs 폴더에 넣는 파일·캡처
40여 개 스킬→/start /build /run /report
계획 확인·운영 보호→허락 버튼, 원본 파일은 고치지 않기
배움·인수인계→만든 자동화를 문서로 남겨 다음에도 /run

처음부터 다섯 겹을 다 갖출 필요는 없어요. 오늘은 내 일 하나를 정확히 적어 두는 것부터 시작합니다.
